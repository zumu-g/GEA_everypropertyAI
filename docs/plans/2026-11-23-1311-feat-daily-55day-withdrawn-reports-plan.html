Goal Capsule

Daily 55-day and withdrawn listing reports

Outcome. Each morning Stuart receives two short email reports for Casey and Cardinia: listings that reached 55 days on market without selling since yesterday, and listings withdrawn since yesterday. Both are call lists for the sales team (ST).

Format. Status-update format per the standing rule: an A4 HTML report, printed to PDF, emailed with the PDF and HTML attached and a short covering note.

Success. The reports arrive every morning; each row is one real property (no portal duplicates); an empty report is clearly "none today", never confused with a broken feed.

Requirements — 55-day report

R1List active listings (Casey + Cardinia) whose days on market crossed 55 since the previous report. Only new entries; not the full 55+ list.
R2Days on market = today − portal listed date. Where no listed date exists, use the date first seen and flag the row "first-seen" (it understates).
R3One row per address across REA, Domain and Homely (latest-seen copy wins), matching the suburb_stats dedupe from PR #82.
R4Row fields: address, suburb, beds/baths/cars, property type, current asking price, price-cut history (count and total %), agency and agent, listing link.
R5Group rows by suburb. Header shows today's new count and the total active at 55+ days.

Requirements — withdrawn report

R6List listings that became withdrawn since the previous report, detected by the daily source sweep (missed two consecutive crawls).
R7Exclude 21-day backstop closures (they are ~3 weeks late, and include the 23/11 cleanup). Show only a one-line count of them.
R8Never list a sold listing. If a sale is matched later, it drops from future reports.
R9Row fields: R4 fields plus days on market at withdrawal and last asking price. Grouped by suburb, one row per address.

Requirements — delivery

R10Run once each morning, after the morning feeds and the lifecycle reconcile (about 11:00 Melbourne). Never inside quiet hours.
R11Email to Stuart via the existing Resend setup: covering note with the two counts, PDF and HTML attached. One email carrying both reports, or two emails, is a planning choice.
R12If an on-market feed failed or was blocked that morning, the report says so at the top and names the feed.
R13On a day with nothing new, still send a one-line "none today" email.
R14"Since yesterday" is tracked by a stored watermark, so a missed day is caught up on the next run, not lost.

Scope boundaries

  • Out: owner contact details, CRM push, Telegram delivery, rentals.
  • Out: fixing the Homely block and REA page cap (separate work). The reports note when coverage is degraded (R12).

Known data limits

  • Many listings lack a portal listed date, so first-seen days on market undercount until the listed-date backfill fills more rows.
  • Withdrawn means "left the portals with no matched sale yet". Some will later match a sale (R8).
  • Domain Web Unlocker returns a shell page about half the time; PR #81 retries it, but a missed crawl can delay a withdrawal by a day.

Acceptance

A1A test fixture with one address on three sources crossing day 55 produces one row.
A2A listing closed by the 21-day backstop never appears as a withdrawn row; it is counted in the one-line note.
A3A withdrawn listing that is later matched to a sale never appears in a later report.
A4Skipping a day, the next run covers both days (watermark).
A5The PDF is A4 (595 × 842 pt) and the email arrives with both attachments.

Open for planning

  • How sweep-detected closures are told apart from backstop closures (e.g. a close-reason column, or miss_count / removed_at pattern).
  • Where it runs: GitHub Actions workflow beside the feed digest, or a Railway cron route.

Implementation

Key technical decisions

D1Close reason column. Migration 016 adds close_reason text to property_listings: sweep (set by sweepSource when it withdraws), stale (set by the 21-day backstop). Existing closed rows stay null and are treated as not-sweep, so the 23/11 cleanup can never enter the withdrawn report (R7).
D2Run after the reconcile. Feeds run ~08:20–08:55 AEDT; the reconcile runs 01:17 UTC (12:17 AEDT) and does the sold matching R8 needs. The report job runs at 01:47 UTC (12:47 AEDT, 11:47 AEST). Late-morning, outside quiet hours.
D3Watermark in feed_runs. Each successful run writes a feed_runs row (category listing-reports). The next run reports changes since that run_start, default 24 h (R14).
D4Day-55 crossing. basis = listed_date ?? campaign_started_at. A listing is new in the report when basis + 55 d falls in (watermark, now] and it is still active. Dedupe by address_slug, latest last_seen_at wins, as in suburb-stats.ts (R3).
D5GitHub Actions, Node built-ins only, like notify-feed-digest.mjs: PostgREST via fetch, Resend via its REST API with base64 attachments, PDF via the runner's preinstalled Google Chrome (--headless --print-to-pdf). No npm install.
D6One email, two reports. One email per morning: covering note with both counts, attachments 55-day-YYYY-MM-DD.pdf/.html and withdrawn-YYYY-MM-DD.pdf/.html. One send to watch, one place to look.
D7Template. Studio Minimalist A4, black-and-white logo, table per suburb; split a long suburb across sheets rather than overflow.

Risks

  • Resend has no verified domain: the sandbox sender only delivers to the account owner. Confirm the recipient is the owner address, or verify grantsea.com.au.
  • Monday REA full sweeps reopen listings: a reopen resets campaign_started_at, so a reopened listing without listed_date can re-cross day 55 later. Acceptable; flagged "first-seen".

Coding discipline (forward to any agent)

  • TDD. Write the failing test first, make it pass with the smallest change, then refactor. No production code without a test that demanded it. Run the tests before saying "done" and report the result verbatim.
  • The Clean Coder (Robert C. Martin). Say "no" to work that cannot be done properly; estimate honestly; never ship code you have not run; own mistakes plainly; small, frequent commits; leave the code cleaner than you found it.
  • Microservice philosophy. One component, one responsibility; talk through explicit contracts (typed interfaces, schemas, HTTP/MCP APIs), never through shared internals; each piece testable and deployable on its own; failures isolated, with timeouts, retries and clear error envelopes at every boundary.
